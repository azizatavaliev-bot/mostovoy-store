# МОСТОВОЙ — витрина техники с автосинхронизацией из Telegram

Сайт-витрина магазина «Мостовой» (Бишкек): каталог, страница товара, корзина,
рассрочка Zero, трейд-ин, кнопка «Связаться» в Telegram.

Каталог **не ведётся руками**. Сотрудники продолжают публиковать прайс в
Telegram-канале как обычно — бот читает публикации, ИИ разбирает их на товары,
система обновляет цены и наличие, а новые товары заводит сама.

## Стек

Backend — Node.js + Express, база — SQLite (`node:sqlite` из стандартной библиотеки).
Витрина — статические HTML/CSS/JS без сборки. Единственная внешняя зависимость — `express`.

Требуется **Node.js ≥ 22.5** (для встроенного `node:sqlite`).

## Быстрый старт

```bash
npm install
cp .env.example .env    # заполнить ключи
npm run migrate         # создать базу и перенести товары из data.js
npm start               # http://localhost:5190
```

```bash
npm test                # 69 тестов, сеть не используется
```

## Как работает синхронизация

```
Telegram-канал
     │  channel_post / edited_channel_post
     ▼
POST /api/telegram/webhook     ← проверка секрета, дедуп по update_id
     │  кладёт задачу и сразу отвечает 200
     ▼
Очередь sync_jobs (SQLite)     ← блокировка по сообщению, ретраи с backoff
     ▼
SyncService
     ├─ DeepSeek: EXTRACT      ← товары, цены, валюты из текста
     ├─ проверка «цена есть в тексте поста»
     ├─ сопоставление: ключ → алиас → похожесть → LLM
     ├─ новый товар → ProductResearchService (описание, фото)
     └─ запись в products + message_products
     ▼
GET /api/catalog → витрина
```

### Ключевые решения

**Цена только из Telegram.** После ответа модели сервер проверяет, что цена
буквально встречается в тексте поста (`priceAppearsInText`). Если модель
подставила «рыночную» цену из своих знаний — позиция отбрасывается.

**Товар может быть в нескольких публикациях.** Связь `message_products`
означает «этот пост сейчас продаёт этот товар». Наличие = есть хотя бы одна
активная связь в неудалённом сообщении. Товар, убранный из одного поста,
не исчезает с витрины, если он есть в другом актуальном посте.

**Идемпотентность.** Хеш текста + уникальные ограничения в базе + таблица
`telegram_updates`. Повторная доставка того же апдейта и повторная обработка
того же текста не создают дубликатов и не тратят запросы к ИИ.

**Экономия API.** Для уже известного товара модель вызывается один раз
(извлечение цены и наличия). Веб-поиск и генерация описания — только для новых
товаров, результат кешируется в `research_cache` на 90 дней.

## Подключение Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather), скопируйте токен в `TELEGRAM_BOT_TOKEN`.
2. **Добавьте бота администратором канала**: канал → «Управление каналом» →
   «Администраторы» → «Добавить администратора» → выберите бота. Без прав
   администратора Telegram не присылает боту публикации канала.
3. Узнайте ID канала: перешлите любой пост из канала боту
   [@userinfobot](https://t.me/userinfobot). ID выглядит как `-1001234567890`.
4. Придумайте `TELEGRAM_WEBHOOK_SECRET` (любая длинная строка).
5. Зарегистрируйте webhook:

```bash
npm run set-webhook -- --url https://ваш-домен/api/telegram/webhook
```

Проверить и снять:

```bash
npm run set-webhook -- --info
npm run set-webhook -- --delete
```

Под капотом — обычный вызов Bot API:

```
POST https://api.telegram.org/bot<TOKEN>/setWebhook
{
  "url": "https://ваш-домен/api/telegram/webhook",
  "secret_token": "<TELEGRAM_WEBHOOK_SECRET>",
  "allowed_updates": ["channel_post", "edited_channel_post"]
}
```

Telegram требует HTTPS и публичный домен. Локально используйте туннель
(`cloudflared tunnel --url http://localhost:5190`) либо отлаживайте без
Telegram через `npm run resync -- --file post.txt`.

## Ручная синхронизация

```bash
npm run resync -- --all               # перепрогнать все сохранённые публикации
npm run resync -- --message 777       # одну публикацию
npm run resync -- --file post.txt     # текст из файла, без Telegram
npm run resync -- --all --force       # игнорировать совпадение хеша
```

## DeepSeek: что проверено по документации

На 2026-07-24:

- `response_format` поддерживает **только** `{"type":"json_object"}`. Строгой
  JSON Schema (strict structured outputs) в API нет — поэтому ответ модели
  валидируется на сервере (`server/lib/validate.js`), а не принимается на веру.
- В промпте обязано присутствовать слово «json», иначе режим не включится.
- **Встроенного веб-поиска у `/chat/completions` нет.** Модель не ходит в
  интернет и не может знать актуальные URL.
- Модели `deepseek-chat` и `deepseek-reasoner` объявлены устаревшими с
  2026-07-24; актуальны `deepseek-v4-flash` и `deepseek-v4-pro`.

Клиент OpenAI-совместимый, поэтому `DEEPSEEK_BASE_URL` + `DEEPSEEK_MODEL`
позволяют указать любой совместимый endpoint без правок кода.

## Поиск фотографий (ProductResearchProvider)

Раз у модели нет доступа в интернет, ссылки добывает отдельный провайдер,
а модель только выбирает лучшее из найденного.

```
provider.search(запрос)          ← настоящий веб-поиск (Tavily / Brave)
   ↓ страницы, отсортированные по приоритету источника
fetchPageImages(страница)        ← og:image, JSON-LD Product.image, галерея
   ↓ кандидаты
verifyImageUrls(кандидаты)       ← HTTPS, Content-Type, размер, разрешение, SSRF
   ↓ только проверенные URL
DeepSeek RESEARCH                ← описание, характеристики, выбор главного фото
   ↓
enforceAllowedUrls(...)          ← всё, чего не было во входных данных, выбрасывается
```

Последний шаг критичен: модель физически не может подставить выдуманную ссылку —
результат пересекается с белым списком реально найденных и проверенных URL.

Приоритет источников: официальный сайт производителя → официальный магазин
бренда → региональный сайт → крупный надёжный продавец.

**При `PRODUCT_RESEARCH_PROVIDER=none`** поиск отключён: новый товар создаётся
с ценой и названием, статусом `needs_research` и без фотографий. Ссылки
не выдумываются никогда.

Проверка каждой картинки перед сохранением: HTTPS, успешный ответ,
`Content-Type: image/*`, доступность без авторизации, не favicon/логотип/иконка,
не временная подписанная ссылка, ширина ≥ 400 px, разумный размер файла.
Запросы защищены от SSRF: запрещены localhost, приватные подсети и
metadata-эндпоинты облаков, есть таймауты и лимит размера ответа.

Файлы не скачиваются — храним внешние URL. Если картинка перестала открываться,
витрина показывает заглушку.

## Статусы товара

| Статус | Когда | На витрине |
|---|---|---|
| `active` | высокая уверенность, есть описание и фото | да |
| `needs_research` | низкая уверенность, нет фото или описания | да, с заглушкой |
| `sync_error` | ошибка обработки товара | нет |
| `hidden` | скрыт вручную | нет |

Цена и наличие сохраняются всегда, даже когда всё остальное неизвестно.

### Валюта

Пользователь переключает валюту отображения: **$ / с / ₽**. Цена в базе
хранится как есть (число + код валюты) и **никогда не пересчитывается** —
конвертация только на экране, по курсам из `.env`. Курсы обновляются вручную.

### Рассрочка Zero

Сумма к оплате = стоимость ÷ коэффициент срока:

| Срок | Делим на | Пример для 40 000 |
|---|---|---|
| 3 месяца | 0,94 | 42 553,19 |
| 6 месяцев | 0,89 | 44 943,82 |
| 12 месяцев | 0,84 | 47 619,05 |

### Корзина и заявки

Товары добавляются прямо из каталога, там же у смартфонов выбирается цвет.

Каналы связи разделены:

| Кнопка | Куда | Как передаётся текст |
|---|---|---|
| «Купить в WhatsApp» (товар и корзина) | `wa.me/996999110110` | предзаполняется через `?text=` |
| «Связаться в Telegram» | `t.me/mostovoyshop` | копируется в буфер обмена |

Почему по-разному: WhatsApp поддерживает предзаполнение текста ссылкой, а
`t.me/<username>` — **нет**. Параметр `?text=` в Telegram работает только для
`t.me/share/url`, а тот заставляет выбирать получателя. Поэтому для Telegram
текст кладётся в буфер, а ссылка ведёт прямо в чат магазина.

Формат сообщения по одному товару:

```
Здравствуйте! Меня интересует Kindle Paperwhite 16 GB, цвет Jade, за 195 USD. Подскажите, товар сейчас в наличии?
```

Заказ из корзины:

```
Здравствуйте! Хочу оформить заказ:
1. PlayStation 5 Slim — 620 USD
2. DJI Mic Mini — 95 USD × 2

Итого: 810 USD
```

Контакты в подвале: WhatsApp 0999 110 110, телефоны 0700 922 622 (Рахмон)
и 0999 110 110 (рабочий), Telegram [@mostovoyshop](https://t.me/mostovoyshop),
канал [@mostovoyshopp](https://t.me/mostovoyshopp).

## Ограничения

- **Один процесс.** Блокировка обработки сообщения — внутрипроцессная. Для
  нескольких инстансов нужна внешняя блокировка (Redis / advisory lock).
- **SQLite**, и `node:sqlite` помечен в Node как экспериментальный API. Для
  нагрузки выше витринной стоит перейти на PostgreSQL — работа с базой
  изолирована в `server/db/`.
- **Курсы валют статические**, задаются в `.env` и обновляются вручную.
- **Фотографии зависят от провайдера поиска.** Без ключа поиска новые товары
  создаются без фото. Официальные сайты часто отдают галерею через JS, поэтому
  разбор HTML достаёт не все изображения — надёжнее провайдер с картиночным
  поиском (Tavily).
- **Удаление публикации** Telegram боту не присылает: снять товары с продажи
  можно, очистив текст поста или через `resync`.
- Качество распознавания названий зависит от модели — проверяйте на своих постах
  и при необходимости уточняйте промпт в `server/prompts.js`.

## Тесты

`npm test` — 69 тестов, все внешние вызовы замоканы:

- разбор цен и валют (`650$`, `2500 сом`, `$135`, `11 000 сом`, `1,299 USD`);
- «Nintendo 2 470$» → 470, а не 2470;
- публикация с несколькими товарами, редактирование цены, удаление позиции;
- новый и уже существующий товар, товары, различающиеся только цветом;
- низкая уверенность, повторная доставка webhook, недоступная картинка;
- невалидный JSON и временная ошибка модели, два одновременных обновления;
- SSRF-защита, отсев логотипов и подписанных ссылок, выброс выдуманных URL;
- признак, переехавший между полями model/color/variant, не плодит дубликаты;
- формирование ссылок: WhatsApp с предзаполненным заказом и Telegram для связи.
